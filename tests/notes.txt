When I want to interact with a web element, such as filling a username field, I first identify the element using the browser's Inspect/DevTools to understand its attributes. In Playwright, I can use page.locator() with a CSS selector such as an ID or class. Alternatively, Playwright provides built-in user-facing locators such as getByRole(), getByLabel(), and getByTestId(), which allow me to locate elements without necessarily using a CSS selector.

Why is XPath less preferred? The main reason is maintainability. Suppose your HTML is:

Your XPath may break because it depended on the DOM structure. Instead: await page.getByRole('button', { name: 'Continue' }).click(); doesn't care whether the button is inside a div, section, etc. Playwright's preferred approach Generally think: User-facing locator → Test ID → CSS locator → XPath as a last resort For example: // 1. Role await page.getByRole('button', { name: 'Continue' }).click();
// 2. Label await page.getByLabel('Email').fill('abc@gmail.com');

// 3. Test ID await page.getByTestId('email-input').fill('abc@gmail.com');

// 4. CSS/ID await page.locator('#name').fill('Vaishnavi');

// 5. XPath — when you genuinely need it await page.locator('//button[text()="Continue"]').click();

Do we use XPath in Playwright? Yes, Playwright supports XPath through locator(). However, I would not prefer XPath as my first choice. I generally use role-based, label-based, test-id, or CSS locators because they are more readable and usually more maintainable. I would use XPath when a suitable stable locator isn't available.
